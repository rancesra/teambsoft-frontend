Propuesta visual — módulo Catálogo

Cómo se vería el módulo si lo entregáramos hoy. Este documento no reemplaza al wireframe: allá están las reglas del contrato anotadas pantalla por pantalla; aquí está el acabado. Equipo B · versión 1.0 · 2026-09-21.

Para qué sirve en la reunión de los 3 equipos. Si cada módulo elige sus propios colores, el Host App se va a ver como tres páginas pegadas con cinta. Lo que proponemos no es que todos usen este diseño, sino que los tres acuerden las variables de la sección 1. Con eso, tres equipos distintos producen pantallas que parecen la misma tienda.

Lo que está marcado con línea punteada pertenece a otro equipo: lo dibujamos solo para mostrar dónde encaja, no para decidir cómo se ve.

Por qué se ve así y no de otra forma. La etiqueta de stock sale de un dato que el contrato ya devuelve (stock), no de un invento: por eso hay tres variantes y no un genérico “disponible”. La categoría se muestra en mayúsculas pequeñas arriba del nombre porque el producto trae el id (cat-ropa) y el nombre hay que cruzarlo con GET /categorias: ponerlo ahí obliga a resolver ese cruce desde la primera pantalla. Y la paginación arranca en 1, como exige el contrato §2.

Una sola rejilla para todo. La lista de productos usa grid-template-columns: repeat(auto-fill, minmax(198px, 1fr)): el navegador decide cuántas columnas caben. No hay una versión “móvil” que mantener aparte, y eso importa cuando el módulo se monta dentro del Host App y no controlamos el ancho que nos den.
Lo que falta acordar para que esto funcione de verdad: si el Host App trae su propio CSS global, sus estilos y los nuestros se van a pisar. Es parte de la conversación del mecanismo de integración — con componentes web el aislamiento viene incluido; con Module Federation hay que acordar prefijos de clase o usar scoped styles de Vue en todo.
